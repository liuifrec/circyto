# Single-cell Nanopore feasibility assessment

Status: revised two-path architecture and literature inventory, 2026-07-29.
No large sequencing data were downloaded. Runtime work is paused pending
review of this architecture.

## Revised decision: two separate paths

**Go for a bounded, experimental long-read interoperability prototype, and
retain a separate chemistry-gated CIRI-long detector adapter. Do not connect
the two paths through a minimap2 BAM.**

### Path A: generic single-cell long-read interoperability

This path accepts Mandalorion, SiCeLoRe, ScNapBar, and ordinary ONT cDNA. It
uses minimap2 and samtools to produce cell-scoped alignments, QC, and
provenance. It makes no circRNA calls. Mandalorion `SRR4048177` remains the
small smoke dataset.

An optional split/supplementary-alignment inspection may report
`exploratory_bsj_evidence`, but it is diagnostic only, `circRNA_call` is
always false, and its output stays outside the validated `circ` modality.

### Path B: CIRI-long-compatible circRNA detection

This optional path is admitted only for circRNA-enriched libraries with
documented rolling-circle reverse transcription. It passes raw FASTA/FASTQ to
the official CIRI-long interface, not generic minimap2 BAMs, and normalizes
the `collapse` results into versioned circRNA and full-length isoform records.
It preserves library chemistry, observation unit, reference, and detector
provenance. Bulk data remain bulk; no single-cell support is claimed unless
the source experiment genuinely resolves cells.

The source, dependency, output-schema, dataset, and licensing review is in
[ciri_long_feasibility.md](ciri_long_feasibility.md).

The public datasets examined here are useful for testing Nanopore FASTQ
ingestion, cell identity or barcode provenance, splice-aware long-read
alignment, and AnnData/MuData export. They are not defensible conventional
circRNA validation datasets because their RNA molecules were selected or
primed through poly(A)/oligo(dT)-based methods.

Conventional circRNAs are covalently closed and lack a poly(A) tail.
Poly(A)-enrichment is therefore expected to deplete them, while random priming
does not have this bias. This is a library-construction limitation, not
something a downstream detector can recover. The distinction is documented
experimentally in the circRNA detection literature and is also implicit in
circRNA-specific Nanopore protocols, which begin with total RNA and use
rolling-circle reverse transcription and enrichment
([Szabo and Salzman, 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC5565156/);
[CIRI-long protocol](https://www.nature.com/articles/s41596-023-00815-w)).

Occasional non-polyadenylated, internally primed, off-target, truncated, or
chimeric molecules in a poly(A)-designed library do not make that library an
unbiased circRNA assay. In particular, the SiCeLoRe study reported cDNA
molecules lacking terminal poly(A)/poly(T) sequence, but the starting material
was still generated by the 10x 3' v2 oligo(dT) capture workflow. Those reads
cannot support a general claim that conventional circRNAs were retained.

The machine-readable inventory is
[nanopore_candidate_datasets.tsv](nanopore_candidate_datasets.tsv).
Approximate FASTQ sizes were calculated from ENA read-run metadata on
2026-07-29; they are planning estimates and may differ from transfer size or
the raw-read totals reported in publications.

## Recommended first public subset

Use **Mandalorion cell `WT_B1a_Cell1`, complete ONT run `SRR4048177`**.

- It is a complete accession-defined run, not an arbitrary truncation.
- Archive read count, base count, URL, and compressed bytes must be queried
  immediately before transfer and treated as warning-level comparisons rather
  than fixed download constants.
- Its identity is already per-cell, so the first prototype can test manifest
  ingestion, minimap2 splice-aware alignment, alignment QC, and provenance
  without first solving pooled barcode correction.
- Matched Illumina run `SRR4048174` is available from an aliquot of the same
  cell's amplified cDNA if a later concordance check is useful.
- Its old ONT chemistry is a limitation for accuracy benchmarking, but not
  for a format and provenance smoke test.

This subset **must be labelled interoperability-only**. Modified Smart-seq2
uses oligo(dT)-primed poly(A) RNA and is not suitable for circRNA sensitivity,
specificity, or biological validation.

If the per-cell smoke test passes, the smallest useful pooled/barcode-aware
follow-up is the BLAZE GridION run `ERR9958133` (approximately 4.33 GB,
3.42 million reads) from PRJEB54718. It uses modern 10x barcodes and allows an
ONT-only BLAZE whitelist to be compared with the study's Cell Ranger
benchmark. It remains an interoperability test, not circRNA validation.

## Detector compatibility

### Current verdict

**No currently registered circyto detector can legitimately consume ordinary
single-cell Nanopore minimap2 alignments for circRNA calling.**

| Detector/path | Current expectation | Nanopore verdict |
| --- | --- | --- |
| CIRI3 | Alignment-first; circyto's supported paths are unsorted BWA-MEM SAM or the paired-end STAR+BWA hybrid artifacts. CIRI3 identifies and quantifies BSJs from short-read RNA-seq evidence. | **Unsupported.** A minimap2 SAM file being syntactically valid SAM does not satisfy the algorithmic contract. CIRI3's paper presents CIRI-long as a complementary long-read route for full-length information; it does not establish ordinary minimap2 long-read alignments as direct CIRI3 input. |
| CIRI2 / CIRI-full | Short-read BWA-based detection and, for CIRI-full, paired-read reconstruction. | **Unsupported.** Read pairing, clipping/error models, and reconstruction assumptions do not match ordinary ONT cDNA. |
| find_circ3 | Short-read FASTQ/Bowtie2 route. | **Unsupported.** |
| CIRCexplorer2 adapter | Short-read FASTQ/STAR route in circyto. | **Unsupported in the current adapter.** |
| `circyto ciri-long` | Separate, optional RCRT-manifest adapter with readiness checks, shell-free `call`/`collapse`, provenance, and normalized BSJ/isoform/evidence tables. It is deliberately absent from the default short-read detector registry. | **Eligible only for chemistry-confirmed RCRT/circRNA-enriched raw FASTA/FASTQ.** It never consumes generic minimap2 BAM. None of the proposed single-cell poly(A) cDNA datasets has that chemistry. |

CIRI3 formally expects BWA-MEM or its defined STAR+BWA inputs
([CIRI3 paper](https://www.nature.com/articles/s41587-025-02835-1);
[CNCB tool record](https://www.cncb.ac.cn/tools/1?lang=en)). CIRI-long uses
rolling circular reverse transcription, RNase R treatment, poly(A) tailing,
and size selection to produce repetitive long reads that can be reconstructed
as circRNA isoforms. Ordinary single-pass, linear, poly(A)-captured single-cell
cDNA is a different input distribution.

An exploratory long-read BSJ processor would need to reason about minimap2
supplementary/split alignments, strand, query order, splice motifs, mapping
quality, read-through/template-switch artifacts, and repeated BSJ traversal.
It cannot be implemented by converting a BAM to SAM and invoking a short-read
detector. Ordinary Nanopore cDNA reads are often kilobases long and have a
different substitution/indel error profile from Illumina reads; their split or
supplementary alignment evidence is not equivalent to the short-read chiastic
clipping and paired-read rescue evidence expected by the current CIRI3 path.

## Revised two-path architecture

The paused Phase 2 implementation covers only Path A through the isolated
`circyto nanopore` command group. See
[`nanopore_interoperability.md`](nanopore_interoperability.md). It remains an
experimental interoperability route and does not change the verdict below
about biological circRNA validation.

```text
Path A: ordinary long-read cDNA

archive metadata + raw/per-cell FASTQ
        |
        v
versioned Nanopore library manifest
        |
        +-- already per-cell ----------+
        |                              |
        `-- pooled -> external or      |
            imported barcode/UMI       |
            assignment + audit table   |
                                       v
                            Manifest v1, one row per cell
                                       |
                                       v
                       minimap2 splice-aware alignment
                                       |
                                       v
               alignment manifest + long-read provenance
                                       |
                                       +--> QC and provenance
                                       |
                                       `--> optional diagnostic-only
             exploratory long-read BSJ evidence (optional)

No circRNA calls; no CIRI3; no CIRI-long; no validated circ modality.

Path B: RCRT/enriched circRNA libraries

raw FASTA/FASTQ + chemistry-gated manifest
        |
        v
 CIRI-long call -> sample cand_circ.fa
        |
        v
 CIRI-long collapse
        |
        +--> normalized circRNA records
        +--> normalized full-length isoform records
        `--> retained per-read detector evidence and provenance
```

The barcode step should initially **import** published assignments, a barcode
whitelist, or an externally tagged BAM rather than adding BLAZE, SiCeLoRe,
ScNapBar, or wf-single-cell as a circyto dependency. This keeps circyto
dependency-light and makes the origin of cell identity explicit.

For cDNA reads, the initial minimap2 recipe should be explicit and versioned,
for example a splice-aware genomic alignment based on `-ax splice`. Dataset
methods used variants of this preset, but flags such as strand assumptions,
known-junction guidance, secondary alignment handling, and `--MD` must be
selected and recorded rather than copied across protocols without review.

Exploratory Path A BSJ evidence must remain separate from validated short-read
circRNA calls and from Path B CIRI-long results:

- artifact name: `exploratory_bsj_evidence`
- rows: the same canonical biological cell IDs used by existing modalities
- records: conservative query/reference-order inversion patterns with all
  supporting segment details and reason codes
- call status: always false
- provenance: full dataset, library, barcode, alignment, subset, reference,
  and workflow provenance

Non-detection in this sparse, poly(A)-depleted context must never be encoded or
described as a biological negative.

## Required provenance

The future path must preserve the existing workflow summary and add, without
renaming current fields:

- dataset, study, sample, experiment, and run accessions
- source URLs, retrieval date, checksums, and an exact subset rule
- organism, tissue/cell type, donor when applicable, and library ID
- protocol, RNA selection/priming, read technology, ONT instrument and
  flow-cell/kit chemistry when known
- basecaller, version, model, and original versus re-basecalled status
- cell barcode and UMI designs, assignment software/version, whitelist source,
  assignment status, confidence field, and whether matched Illumina was used
- reference assembly/accession, FASTA checksum, annotation release/checksum
- aligner, version, preset, complete command, sortedness, and retained SAM tags
- candidate-caller name/version, compatibility status
  (`experimental-unvalidated` until the gates below pass), parameters, and
  counting unit
- workflow UUID, circyto version, timestamps, restart/cleanup state, and input
  and output record counts

At minimum, a future pooled-library manifest should contain:

```text
library_id  read1  dataset_accession  run_accession  protocol
read_technology  rna_selection  barcode_method  barcode_state
barcode_whitelist  umi_method  basecaller  basecaller_model
source_url  sha256  subset_rule  n_input_reads
```

After barcode assignment, the existing Manifest v1 should be emitted with one
row per cell and these fields preserved as optional columns. Alignment
manifest extras should additionally record `aligner_version`,
`alignment_preset`, `reference_accession`, and `annotation_release`.

## Revised CLI boundary

Path A remains an isolated Nanopore interoperability command group:

```bash
circyto nanopore query-run \
  --accession SRR4048177 \
  --expected srr4048177 \
  --output archive_metadata.json

circyto nanopore validate-manifest \
  --manifest long_read_manifest.tsv \
  --strict

circyto nanopore align \
  --manifest long_read_manifest.tsv \
  --reference reference.fa \
  --reference-id EXPLICIT_REFERENCE_ID \
  --reference-build EXPLICIT_REFERENCE_BUILD \
  --reference-sha256 EXPECTED_FASTA_SHA256 \
  --outdir work/nanopore

# Separate and opt-in; never a circRNA caller
circyto nanopore inspect-bsj \
  --alignment-manifest work/nanopore/nanopore_alignment/alignment_manifest.tsv \
  --outdir work/nanopore/exploratory_bsj_evidence
```

Path B uses a separate detector-adapter command family:

```bash
circyto ciri-long validate-manifest \
  --manifest ciri_long_libraries.tsv

circyto ciri-long call \
  --manifest ciri_long_libraries.tsv \
  --reference reference.fa \
  --annotation annotation.gtf \
  --outdir work/ciri_long

circyto ciri-long collapse \
  --call-manifest work/ciri_long/call_manifest.tsv \
  --reference reference.fa \
  --annotation annotation.gtf \
  --outdir work/ciri_long/collapse

circyto ciri-long import \
  --collapse-dir work/ciri_long/collapse \
  --outdir work/ciri_long/normalized
```

The adapter must invoke the external executable with argument arrays and
preserve exact commands. `call` receives raw reads. `normalize` emits
versioned tables and never assumes that samples are cells. A later
implementation may combine `collapse` and `normalize` if that remains compact,
but it must not merge Path A and Path B.

No AnnData/MuData CLI change is proposed at this stage.

## Precise code changes required after review

No further runtime changes below should be made until this architecture is
approved.

1. **Complete and review Path A only**
   - Keep the long-read manifest, ENA query/download helper, minimap2/samtools
     alignment, QC, and provenance modules isolated under the Nanopore command
     group.
   - Change exploratory BSJ inspection from an alignment default to a separate
     opt-in diagnostic command.
   - Keep cell-scoped paths, streaming alignment, strict reference identity,
     archive identity/warning checks, and hermetic fake-executable tests.
   - Do not download `SRR4048177` in default tests or encode a fixed transfer
     size.

2. **Defer pooled barcode handoff**
   - A later importer may join external read/cell assignments and emit
     per-cell long-read manifest rows with preserved provenance.
   - Do not implement barcode calling or vendor-specific basecalling in the
     smoke increment.

3. **Add a separate versioned Path B manifest**
   - Create a circRNA-library schema without modifying Manifest v1 or the
     Path A manifest.
   - Require raw FASTA/FASTQ, observation unit, enrichment protocol,
     `rolling_circle_rt_confirmed`, protocol citation, accessions, checksums,
     and explicit reference/annotation identities.
   - Reject false or unknown RCRT status. Do not offer a force flag that
     relabels ordinary ONT cDNA as compatible.

4. **CIRI-long adapter (implemented; official-demo execution pending)**
   - Extend `DetectorCapabilities` with backward-compatible defaults for
     supported read technologies and required library chemistry.
   - Reject `read_technology=nanopore` for existing short-read detectors with
     an informative error.
   - Leave the current unregistered CIRI-long wrapper disabled during Path A.
   - Invoke official `CIRI-long call` on raw FASTA/FASTQ and `collapse` on its
     candidate files. Never route the generic minimap2 BAM into this adapter.
   - Normalize `.info`, `.expression`, `.isoforms`, and `.reads` into
     versioned circRNA, full-length isoform, expression, and evidence records
     while retaining the unmodified detector artifacts.
   - Make the CIRI-long environment optional and keep it out of default
     dependencies and CI. Use synthetic tandem-repeat fixtures and a fake
     executable for hermetic adapter tests.

5. **Keep Path A exploratory evidence diagnostic-only**
   - Expose the existing conservative inspection logic only through the
     separate opt-in command.
   - Mark outputs `experimental-unvalidated`; record artifact filters and the
     read-versus-molecule counting unit.
   - Do not route minimap2 output through CIRI3 or another short-read adapter.

6. **Export boundaries**
   - Do not change AnnData/MuData export during the Path A smoke increment.
   - If Path A alignment objects are exported later, keep them outside the
     established `circ` modality.
   - Do not put bulk CIRI-long samples on a single-cell observation axis.
     Design the Path B sample/isoform export only after its normalized schemas
     and observation units are reviewed.

7. **Tests and fixtures**
   - Retain Path A's tiny synthetic ONT-like FASTQ, split-alignment records,
     fake minimap2/samtools, and offline archive responses.
   - Add Path B synthetic tandem-repeat reads, representative fake
     `.info`/`.expression`/`.isoforms`/`.reads` outputs, and a fake CIRI-long
     executable only when that adapter is implemented.
   - Test chemistry admission, sample-versus-cell observation units, output
     parsing, coordinate normalization, provenance propagation, and the rule
     that zero support is `not_observed`, never `biological_negative`.
   - Keep all default tests independent of minimap2, samtools, BLAZE,
     CIRI-long, CIRI3, BWA, STAR, and network access.

## Go/no-go criteria

### Gate A: experimental long-read interoperability

Proceed if all are true:

- an accession-defined complete small run can be retrieved with checksums and
  no ambiguity about cell or library identity
- FASTQ parsing, read counts, and subset provenance are reproducible
- minimap2 produces parseable splice-aware alignments while preserving the
  read and cell identity needed downstream
- every cell or imported barcode has auditable assignment provenance
- reference identity, FASTA checksum, exact commands, QC definitions, and
  provenance survive alignment-manifest and JSON reload
- the optional long-read modality is isolated from established `circ` results
- default tests remain synthetic and executable-free
- the manuscript labels the result experimental interoperability

No-go if cell identity cannot be audited, the run requires undocumented
barcode reconstruction, reference/protocol metadata cannot be recovered, or
the implementation would alter existing default outputs.

### Gate B: biological circRNA validation

Do not make a validation claim unless all are true:

- the source library is explicitly poly(A)-independent (for example total RNA
  with rRNA depletion/random priming) and was designed to retain circRNAs
- the library chemistry is compatible with the chosen long-read circRNA
  algorithm; rolling-circle callers receive rolling-circle libraries
- appropriate positive controls and linear/template-switch artifact controls
  are available
- the caller is validated for the relevant ONT chemistry and single-cell
  depth, with reproducible BSJ evidence and an explicit false-positive policy
- a subset of calls has orthogonal support, such as RNase R enrichment and
  divergent-primer validation, or a justified public truth set
- non-detection is reported only as `not observed under this assay`, never as
  a biological negative

None of the single-cell candidates in this inventory passes Gate B. The
official CIRI-long demo and CRR194209 are eligible for future bulk
detector-adapter testing, not single-cell biological validation.

## Manuscript-safe wording

### Wording supported by the current feasibility result

> We assessed experimental interoperability with public single-cell Oxford
> Nanopore cDNA data. Because the source protocols use poly(A)/oligo(dT)-based
> transcript capture, this analysis is limited to read ingestion, cell
> provenance, splice-aware alignment, and alignment QC. It does not evaluate
> biological circRNA sensitivity and is not presented as circRNA validation.

After a successful Mandalorion smoke test:

> As a bounded interoperability example, circyto ingested an
> accession-defined Nanopore FASTQ from one physically isolated mouse B1a cell,
> recorded source and alignment provenance, performed splice-aware long-read
> alignment, and produced alignment QC without changing the established
> short-read circRNA modalities. The poly(A)-primed source library is expected
> to deplete conventional circRNAs; therefore, no biological inference was
> made from circRNA non-detection.

### Wording for a future CIRI-long interoperability result

After the official demo and CRR194209 reproduce successfully, the following
bounded wording is supportable:

> We demonstrated experimental interoperability with CIRI-long using public
> bulk Oxford Nanopore libraries generated with circRNA enrichment and
> rolling-circle reverse transcription. Detector outputs were normalized with
> protocol, reference, and software provenance. This result does not establish
> single-cell circRNA support or biological validation of individual calls.

### Conditional wording for future biological circRNA validation

This wording is not currently supported. It becomes permissible only after
Gate B passes:

> We evaluated circRNA detection using a single-cell Nanopore library
> explicitly designed to retain non-polyadenylated RNA and processed it with a
> long-read circRNA method matched to the library chemistry. Candidate BSJs
> were assessed against stated artifact controls and orthogonal validation;
> absence of support was interpreted as non-observation under the assay rather
> than evidence of biological absence.
